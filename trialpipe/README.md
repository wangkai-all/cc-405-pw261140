# trialpipe — 实验数据管道（样本冻结 / 结局分版 / 区间估计）

从空目录构建的三服务虚构实验数据管道。**只做确定性统计区间计算，
不训练任何模型，也不对观察性数据作因果断言。**

## 1. 设计原则

实验分析先确定样本与分组，再等待结局数据成熟。围绕这条主线：

1. **分组接入、样本冻结、统计报告是三个独立服务**，各自独立部署、
   独立端口，通过只追加台账与文件存储协作，不共享内存状态。
2. **后补结果不能偷偷改变入组人群。** 样本清单在 as-of 时点冻结后
   内容寻址、不可变；迟到退出、分组修订、身份纠错、补结局都是台账里
   的新事件，只影响之后的新冻结，绝不回溯改写旧清单。
3. **身份纠错必须有明确处理。** 纠错事件强制携带原因与生效时间戳，
   保留旧 ID→新 ID 别名链；冻结按严格时点穿越（point-in-time）投影，
   报告取数通过别名解析定位结局，同时保留冻结时 ID 用于溯源。
4. **冻结样本后分版补结局，或重建新样本报告。** 同一冻结人群可挂
   v1/v2 多版结局出多版报告；另起清单即另起人群。
5. **不能把两个不同人群的指标直接相减。** 跨报告比较先做人群指纹
   核对：同人群才允许并列对照；不同人群只展示比较前提并拦截相减。
6. **旧报告始终可还原原输入。** 每份报告持久化逐样本输入快照
   （内容哈希命名），即使报告被新版取代（superseded），原始输入
   仍可逐字节还原并复算。

## 2. 服务架构

| 服务 | 端口 | 职责 |
|---|---|---|
| 分组接入 intake | 8101 | 只追加事件台账（哈希链）、只读查询、链验真 |
| 样本冻结器 freezer | 8102 | as-of 不可变样本清单的构建/幂等读取 |
| 统计报告 reporting | 8103 | 结局分版取数、区间计算、报告生命周期、比较前提、输入还原 |

数据流：

```
入组/分组/纠错/修订/退出/结局
        │  POST /events（只追加，SHA-256 哈希链）
        ▼
  data/ledger/events.jsonl
        │  严格 as-of 时点投影（晚于时点的事件不可见）
        ▼
  data/manifests/<内容哈希>.json        ← 不可变冻结清单
        │  报告只在清单成员内取数，分组以清单为准
        ▼
  data/reports/<报告哈希>.json          ← 结果 + 生命周期状态
  data/reports/inputs/<输入哈希>.jsonl  ← 逐样本原始输入快照
```

### 事件类型（全部只追加，任何修改都是新事件）

| 类型 | 关键字段 | 约束 |
|---|---|---|
| `enrollment` | subject_id, enrolled_at | 同一 ID 不可重复入组 |
| `assignment` | subject_id, group, assigned_at | — |
| `id_correction` | old/new_subject_id, reason, **corrected_at** | 新 ID 不得已被占用；新旧 ID 不得相同 |
| `group_revision` | old/new_group, reason, revised_at | 旧组必须等于当前组，否则拒绝 |
| `withdrawal` | withdrawn_at, reason | 不删人，仅记录退出时点 |
| `outcome` | outcome_name, value, **version**, as_of | 同 (人,结局,版本) 不可重复；修订必须升版本号 |

## 3. 统计方法（纯标准库，真实区间计算）

所有数学在 `trialpipe/stats.py`，无第三方依赖，结果完全确定性可复现：

- 标准正态分位数：Acklam 有理逼近 + Newton 精修
- Student-t 分布函数/分位数：正则化不完全 Beta 函数（Lentz 连分式）+ 二分反演
- 二分类结局：单组 **Wilson** 区间；组间差 **Newcombe hybrid-score** 区间；
  合并方差两比例 z 检验
- 连续结局：**Welch 不等方差 t** 区间（含 Welch–Satterthwaite 自由度与 p 值）
- 固定种子百分位 **bootstrap**（独立 LCG，仅作敏感性核对，非主推断方法）

> 所有结果对象都带 `causal_note`：区间只量化抽样不确定性；
> 除非随机分配且识别假设成立，不能据此宣称因果。

## 4. 快速开始

需要 Python 3.11+（仅标准库）。**推荐用一键脚本**，它会从空目录启动：

```bash
./run_demo.sh
```

手动分步：

```bash
# 终端 1/2/3：分别启动三个独立服务（也可用 --service all 同进程演示）
python3 -I run_services.py --service intake
python3 -I run_services.py --service freezer
python3 -I run_services.py --service reporting

# 跑端到端 HTTP 演示（要求空台账；非空会被前置检查拒绝）
python3 -I demo_scenario.py

# 离线领域不变量测试（不起 HTTP，临时目录，自动清理）
python3 -I smoke_test.py

# 数学模块验证（教科书固定值）
python3 -I verify_stats.py
```

仪表盘：服务启动后用浏览器打开 `web/dashboard.html`
（原生 HTML/JS，无构建步骤；CORS 已在三个服务开启）。

> 说明：本环境的 Python 用 `-I` 隔离运行（忽略环境变量与用户站点包，
> 防止不可信目录里的同名模块被导入）。`-I` 隐含 `-P`，脚本目录不自动
> 进 `sys.path`，因此各脚本开头用 `__file__` 显式插入项目根。

## 5. 演示覆盖的场景（`demo_scenario.py`）

12 名虚构受试者、治疗 T / 对照 C，二分类缓解 + 连续评分两个结局：

1. 入组与分组接入，台账哈希链验真
2. **首次冻结 M1**（as_of 11-05），清单不含任何结局字段
3. 结局 v1 成熟 → 报告 R1 草稿 → 批准
4. **迟到退出**（S10，11-12）：M1 成员与哈希不变；更晚 as_of 的 M2 才排除
5. **分组记录修订**（S07：T→C，带原因与旧值前提校验）：M1 冻结分组保持 T；
   新旧组相同/旧值不符的修订被拒绝
6. **身份纠错**（S12→S12-R，带原因与时间戳）：M1 时点不可见、M2 可见且带别名
7. **结局 v2 分版** → 同人群新报告 R2 批准 → R1 变 superseded 但可还原 v1 输入
8. **计算中断**：报告停在 `interrupted` 且无结果段、禁止批准；
   `resume` 从固定输入快照确定性复算，结果与未中断一致
9. **重建新人群** M2（n=11）与新报告 R3
10. **比较前提**：R1/R2 同人群可并列；R2/R3 不同人群，直接相减被拦截
11. 逐样本解释 + 台账最终验真

## 6. 关键不变量（`smoke_test.py` 自动断言）

- 哈希链：任何字节篡改都在 `read(verify=True)` 时报错
- 坏事件（缺字段、撞 ID、修订前提不符、版本冲突）在**落盘前**被试重放拒绝
- 同 as_of 重复冻结：身份哈希与成员逐字段一致，返回同一不可变文件
- 迟到退出/晚到修订/晚到纠错：不改变任何更早 as_of 的清单
- 报告内容寻址：同（清单, 配置, 输入）必然同 report_id；重复创建不降级
  已批准报告
- 中断报告无结果且不可批准；恢复后结果与正常计算一致
- 跨人群作废、跨人群点估计相减均被拒绝；同人群分版允许并列
- 逐样本解释覆盖全部冻结成员（含结局缺失者，明确标注未插补）

## 8. 边界声明

- 数据全部为虚构，仅用于演示管道机制与区间计算。
- 本仓库不存在模型训练代码；bootstrap 是固定种子的确定性重抽样核对，
  不是学习算法。
- 区间、p 值只描述估计的抽样不确定性。对观察性数据，系统在数据结构与
  输出文案两个层面都不支持把组间差异表述为因果效应；随机化分配与
  识别假设是否成立，需由研究设计另行论证。
